# АКГ: интеграция агента с Реестр_факта → PDF — дизайн

Дата: 2026-07-25. Статус: финализирован Alex'ом.

## Зачем

Агент `agent-mode` собирает статистику Дзен / ВК-органики / Тенчата (лучше, чем
серверный Pull+map: периодный Дзен, UI-«Охват контента» ВК, Тенчат которого в
API нет). Нужно, чтобы эти данные автоматически попадали в лист «Реестр_факта»
клиентской Google-таблицы «План-факт…», а оттуда — в еженедельный PDF
собственнику (owner-report-pipeline).

## Что уже есть (сверено на сервере 2026-07-25)

- n8n-движок убран (cutover 07.07): всё на нативном `~/AKG/akg-native/`
  (`server.js` + `nodes/*.js`, Docker). Пути `/webhook/*` сохранены.
- Запись в «Реестр_факта» делает **Apps Script в самой таблице**: GET на native
  `/webhook/akg-report-rows?week=YYYY-Www` → получает строки от `Pull+map` →
  апсертит по ключу **неделя+канал** (дедуп и защита колонки «Комментарий» — там).
- Push-источник — образец `dzen_snapshot.py` → `POST /webhook/dzen-snapshot` →
  нода кладёт в `staticData.json`.
- owner-report-pipeline (cron пн) читает Реестр_факта → 4-стр. PDF. Не трогаем.

## Решения (согласованы)

1. Агент **замещает** каналы Дзен / ВК-**органика** / Тенчат — для них источник
   = агент, Pull+map по ним свой сбор не делает. **ВК-реклама** («Таргетированная
   реклама в ВК», VK Ads API) — НЕ трогаем, остаётся в Pull+map.
2. Все три канала сразу.
3. Агент шлёт **готовые строки** в формате реестра; маппинг живёт в агенте.

## Колонки «Реестр_факта» (сверено, лист gid 1132711560)

| Кол | Название | Пишет агент |
|---|---|---|
| A | Дата начала недели (понедельника) | да (`week_start`, DD.MM.YYYY) |
| B,C | Ключ недели/месяца (авто) | нет (формулы) |
| D | Аудитория | пусто (органика) |
| E | Мероприятие | пусто (органика) |
| **F** | **Канал (детальный)** | да, дословно = `registry_name` |
| G,H,I | Категория/Группа/Ответственный (авто) | нет |
| J | Расходы, ₽ | 0 |
| **K** | **Охват** | да |
| L | Кол-во визитов на лендинг | нет (Метрика, не наше) |
| **M** | **Новые подписчики в соцсетях** | да (прирост) |
| N,O | подписчики email/боты | нет |
| P–U | лиды/сделки/продажи/участники | нет (Битрикс) |
| V | Входы (авто) | нет |
| **W** | **Комментарий** | да |

## Маппинг метрик агента → строки

Одна строка = один канал за неделю. `channel` (F) — дословное имя из справочника
клиента. Заполняем A, F, K, M, W (остальное 0/пусто — досчитает Битрикс-часть).

| Канал (F) | K (Охват) | M (подписчики) | W (Комментарий) |
|---|---|---|---|
| Корп. блог Дзен / Дзен ЛБ | показы | подписки (прирост, кол. J XLSX) | «N публ.; подписчиков всего S; период W» |
| Корп. ВК-сообщество / ВК ЛБ | Охват контента | Δ подписчиков | «просмотры контента X; период W» |
| Корп. ВК блог | Просмотры канала | — | период W |
| Корп. ВК-видео | Просмотры видео | — | период W |
| Тенчат ЛБ | Охват записей | прирост подписчиков | «⚠ период: последние 7 дней на DD.MM (платформа не даёт выбор)» |

**Прирост подписчиков (M):** где метрика уже прирост за период — берём напрямую
(Дзен `subs` из by-event XLSX; Тенчат `subscribeCount` — прирост за 7 дней). Где
метрика — текущее число (ВК `members`) — native-нода считает Δ из истории
снимков по неделя+канал (первую неделю Δ=0).

## Период

- **Дзен** — точная неделя (`from`/`to` в XLSX by-event). ✅
- **ВК** — точная неделя через датапикер дашборда: пресет «Прошлая неделя» или
  произвольный диапазон под `--week`. Реализация: открыть датапикер, выставить
  диапазон [start, end], «Показать», затем снимать метрики. ✅
- **Тенчат** — только «последние 7 дней» на дату запроса (ни UI, ни API период
  не принимают — проверено). Пишем с пометкой в W + `needs_review`. Приближение;
  запускать сбор ближе к концу отчётной недели. ⚠️

## Архитектура

```
агент (машина/сервер клиента)              akg-native (сервер Маши)         таблица
 collect.py --all
   ├─ сбор Дзен/ВК/Тенчат (точный период Дзен/ВК; Тенчат — 7 дней)
   ├─ core/registry_rows: ChannelResult → строки реестра (F/K/M/W)
   └─ POST {week, rows[], source} ─► /webhook/agent-metrics?key=SECRET
                                        └─ нода Agent_Metrics_Code.js
                                             staticData.agent_rows[week][channel]
                                             + история подписчиков (для Δ)
 Apps Script ──GET── /webhook/akg-report-rows?week=W
                        └─ Pull+map: замещаемые каналы берёт из agent_rows[W],
                           свой сбор Дзен/ВК-органики/Тенчата НЕ делает;
                           Битрикс/ВК-реклама/Метрика/TG — как есть
                     ◄── строки ──
 Apps Script апсерт по неделя+канал ─────────────────────────────► Реестр_факта
 owner-report cron пн ─► читает Реестр_факта ─► PDF
```

### Серверная часть (правки akg-native, у Маши)

1. `nodes/Agent_Metrics_Code.js` — POST-приём: валидирует payload, кладёт
   `staticData.agent_rows[week] = {channel: row}` (последний прогон перезаписывает),
   ведёт `staticData.agent_subs_history[channel] = [{week, members}]` для Δ,
   проставляет M = текущее − прошлонедельное там, где прислано текущее число.
2. `server.js` — роут `POST /webhook/agent-metrics` (+ проверка `?key=`).
3. `Pull_+_map_to_detailed_channels.js` — для замещаемых каналов: не вызывать свой
   `fetchDzen`/`fetchVkCommunities`/Тенчат-сбор; подмешать строки из
   `agent_rows[week]`. Точки правок определит разбор файла на этапе плана.

### Агентская часть (наш репо)

1. `config` / `config_local`: `WEBHOOK_URL`, `WEBHOOK_KEY`; к каждому
   каналу/вкладке — `registry_name` (имя в колонке F).
2. `core/registry_rows.py` — чистый маппер `list[ChannelResult] → list[dict-строк]`
   по маппингу выше. ВК разворачивается в несколько строк (сообщество/блог/видео).
   Строки каналов со `status` ≠ `ok`/без данных — не включаются.
3. `collect.py` — после `--all`: если `WEBHOOK_URL` задан, POST строк на native;
   статус отправки в консоль/summary. Локальные JSON/сводки — как раньше.

## Ошибки

- Канал `failed`/`auth_required` → строку не шлём (не затираем хорошие данные).
- POST-сбой не рушит прогон — локальные файлы остаются, лог + возможность повтора.
- Тенчат с несовпавшим периодом — шлём с пометкой, не молча.

## Вне рамок

- Apps Script (дедуп/защита W) — не трогаем.
- owner-report / PDF — не трогаем (соберётся из реестра).
- ВК-реклама (VK Ads) — остаётся на API в Pull+map.
- Датапикер ВК и клик-детали — уточняются кодом при реализации.
