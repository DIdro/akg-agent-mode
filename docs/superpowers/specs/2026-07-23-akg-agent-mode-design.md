## Архитектура

Выбран гибрид (вариант 3 из обсуждения): разведка потоков — агентом (Claude + Playwright MCP),
продакшн — детерминированные скрипты; общий персистентный профиль браузера.

```
akg/agent-mode/
  profile/           # user-data-dir браузера; сессии живут тут; НЕ коммитить/не копировать наружу
  collect.py         # оркестратор: --login | --channels dzen,vk,tenchat | --all
                     # период: по умолчанию последняя завершённая ISO-неделя (как в клиентском
                     # пайплайне, дедуп-ключ там неделя+канал); override флагом --week 2026-W30
  channels/
    dzen.py          # Студия → экспорт XLSX → парсинг (портировать parse_xlsx из dzen_snapshot.py)
    vk.py            # обход 4 вкладок статистики → XHR-перехват / скриншот+vision
    tenchat.py       # кодифицируется после разведки
  vision.py          # скриншот → цифры через Claude API (vision) + валидация
  out/<ISO-week>/    # результат: *.json, *.png, *.xlsx
```

- Браузер: Chromium через Playwright, headed (видимое окно) — меньше антибот-детекта,
  на тесте видно происходящее. `--login` открывает окно для ручного логина во все кабинеты.
- Техника извлечения — своя на канал, по убыванию точности источника:
  1) файловый экспорт (Дзен XLSX — попостовые данные, со скриншота не снять);
  2) перехват XHR-JSON, из которого страница рисует дашборд (ВК/Тенчат — если разведка покажет читаемый JSON);
  3) скриншот + vision (Claude API) — основной для ВК-вкладок, если XHR мутный, и для Тенчата.
  Селекторы используются только для НАВИГАЦИИ (клик по вкладке), не для чтения цифр.
- Скриншоты вкладок сохраняются в out/ всегда (сверка глазами, как у Маши).

## Формат результата

Один JSON на канал за прогон:

```json
{
  "channel": "vk",
  "period": {"from": "2026-07-14", "to": "2026-07-20"},
  "metrics": {"content_reach": 17600, "video_views": 3600, "channel_views": 504, "...": 0},
  "source": "vision",            // xlsx | xhr | vision
  "screenshots": ["out/2026-W30/vk_community.png"],
  "status": "ok",                // ok | auth_required | failed
  "needs_review": false,
  "collected_at": "2026-07-23T14:00:00+03:00"
}
```

Vision-валидация: нормализация «17,6K»→17600, проверка формата и здравого диапазона;
при сомнении — `needs_review: true`, не тихая запись.

## Ошибки

- Каналы независимы: исключение в одном не прерывает остальные; итоговая сводка ok/fail по каналам.
- Любое падение → скриншот текущего состояния страницы в out/ для диагностики.
- Разлогин детектируется явно (редирект на страницу входа) → статус `auth_required`
  с сообщением «зайди `collect.py --login`», а не загадочный крэш.
